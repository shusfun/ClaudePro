# ClaudePro 验证记录

当前发布版本 0.1.4。下文 0.1.0 条目保留为当时验收记录。

验证平台：Windows 11 25H2 x64，Go 1.25.0，Node.js 22.18.0，Wails v3.0.0-alpha2.117，WebView2 155.0.4283.62。

## 0.1.4 恢复记录与更新修复

- macOS `Country` / `AppleLocale` 不存在时，适配器保存空标签和明确的 `present=0,value=""`。旧校验无条件拒绝空标签，导致 `GetState` 失败；现允许这种完整的缺失键记录，无需修改旧 journal 或迁移格式，其他不完整数据仍拒绝。
- 更新窗口使用 `CheckUpdate` 返回的安装能力，环境读取失败不再被误判成开发构建；检查更新不依赖环境状态加载。移除重复的原始更新事件消费，以 RPC 结果为界面权威来源。下载开始前更新阶段，避免覆盖下载完成事件。
- 修正 Go main 包的版本注入符号为 `main.appVersion`；新增只读 `--version` 输出和 macOS CI 产物版本/更新能力检查。
- 本机 Go 测试、vet、TypeScript 和生产前端构建通过；ego-browser 模拟环境读取失败后仍显示 ZIP、可点击立即更新且调用安装接口。真实系统恢复和自动替换正在运行的应用未执行。

## 0.1.3 macOS 时区回读修复

0.1.2 在 macOS 15.7.9 的一次真实切换中，systemsetup 返回后立即 readlink 遇到 ENOENT，后续恢复检查已能读取目标时区，但因首次写入未经确认而进入需要恢复状态。

0.1.3 对时区链接暂时不存在最多等待 2 秒；权限、路径格式错误立即返回。时区写入和恢复后，对目标时区及自动时区值最多额外等待 3 秒确认，持续不一致仍失败，不绕过恢复冲突检查。新增无系统写入的回归测试，覆盖短暂缺失、持续缺失、权限与格式错误、旧值延迟发布、自动时区不一致以及恢复原值/不存在键。

未重跑管理员授权下的真实系统切换；现有未完成恢复记录仍须由用户在恢复界面明确处理，不自动清除备份。

## 待在可还原 Windows 测试环境执行

没有对当前开发电脑执行真实时区、区域格式或国家地区修改。自动化测试不能替代以下验收。

1. 建立虚拟机快照，用普通用户安装 WebView2、CLI、Desktop。记录 `tzutil /g`、`Get-Culture`、`Get-WinHomeLocation`，导出 `HKCU\Control Panel\International`（包括 Geo）。设置自定义日期、小数和货币格式。
2. 配置不同目标。运行 Claude 时点击切换，应提示保存关闭且不创建新备份；关闭全部会话后重试。
3. 接受时区 UAC，核对三项实际设置。确认显示语言、输入法、首选语言列表、网络没有变化，journal.json 保存完整自定义格式。
4. 从中文及空格路径启动原生和 npm CLI，检查工作目录、可见终端、现有登录状态。测试 MSIX、普通 EXE、已运行 Desktop 和托盘隐藏情形。
5. 关闭 Claude 后恢复，核对所有原始值和自定义格式；恢复顺序为国家地区、区域格式、时区，日志保留至下次归档。
6. 取消 UAC 应报告失败并回滚，或明确提示需要恢复。标准用户输入其他管理员凭据时，当前用户区域设置仍应属于启动界面的原用户。
7. 切换后重启应用及 Windows，应可恢复；分别在意图写入后、系统写入后、恢复期间中断应用或虚拟机，重启后禁止新切换、核对实际值并继续恢复。
8. 切换后在 Windows 设置外部修改，分别测试保留和恢复原值；冲突对话框显示后再次修改，旧选择应失效。
9. 在测试副本损坏 journal.json、移除步骤、清空原值，确认停止写入并保留文件。测试磁盘写保护/空间不足，未保存意图不能继续修改。
10. 目标环境退出提醒、保留退出再恢复、第二实例、重复点击和长操作关闭窗口均应符合互斥规则。
11. 在无 WebView2 虚拟机检查中文提示和无系统写入；安装 Evergreen x64 Runtime 后应正常启动。

完成这些实际验收后，才能声明对应 Windows 与客户端版本的端到端切换和恢复已验证。
